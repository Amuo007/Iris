**Will it run out of memory?** No — but there was one slow leak, now fixed. Total memory rose about
80 MB over four hours; the peak comes from PDFs open in tabs and drops when they close. Looking per
process afterwards: Iris's main process held only 30 MB of JavaScript, but the browser window held
142 MB, because the panel kept every step's screenshot after hiding the step (it shows the newest 80).
Fixed: hidden steps let go of theirs. Measured with 300 steps of fake screenshots: **119 MB before,
36 MB after** — so a run of any length now stays flat. **Does the server keep up?**
Yes, with the brief drops above. Calls got slower in hours 4–5 for two reasons: my other tests shared
the server then (each request waits its turn), and the prompt grew while the cached part did not —
which is what moving the summary of older steps (found in this run) is for.

## 7. What is still weak
- **Speed.** About 8 s a step with the server to itself (most of it is the model reading the prompt
  and the screenshot; it writes only ~80 tokens). A simple application takes ~3 minutes, a
  Greenhouse- or Lever-style one 3.5–4. Two Iris windows take turns, so each runs at half speed. Auto
  thinking does not help on this model (measured); 1024 px screenshots did (now the default).
- **Every resume costs one full re-read on the server (~35 s).** Measured at 18:05: the step after
  `tailor_resume` had 0 cached tokens and took 42 s (10K tokens), the steps around it 6–17 s. The
  tailoring request (and cover letters, the answer check) pushes the agent's cached prompt out. With
  `--parallel 5` (set on the server on Oct 7) they should land in different slots; that they do not
  suggests the server now keeps one — the Oct 11 Lemonade upgrade reset other settings
  (`extra_models_dir`), so it is worth checking `llamacpp.args` there. I did not touch the server.
- **Pages built by JavaScript** (many company career sites) cannot be read by look-ups, so there
  tailoring relies on what Iris noted while reading (now saved as it reads). Greenhouse, Lever,
  Ashby and Workday postings are read directly (the last two through their public JSON).
- **Fit is the model's judgement.** It now loses points for missing years, but "must-have" vs
  "nice-to-have" is still the model's call; check the first few fits against your own view and set
  the cutoff (Settings → Applying) to taste.
- **CAPTCHAs** are never solved — by design. Iris stops (one job), or marks the job *Needs you*,
  notifies you and moves on (non-stop).
- **Not tested on real sites:** Workday/iCIMS/Taleo with a real account, LinkedIn Easy Apply, your
  real Gmail for confirmation links. All of these need your accounts; the local copies pass.
- **Judging papers** is stricter after 10 judgements (97 % → 69 % kept, section 4c), but still the
  model's opinion.
- **Cover letters** are fact-checked sentence by sentence, but their style has not been read by a
  person yet — worth reading the first few.
